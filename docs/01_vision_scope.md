# **Vision & Scope (Видение и границы)**

**1. Идея проекта:**
Создание единой информационной системы для автоматизации деятельности гостиничного комплекса. Система должна заменить разрозненные Excel-таблицы и бумажные журналы, обеспечив централизованное управление номерным фондом, бронированиями, расчетами с гостями и работой персонала.

**2. Контекст проекта:**
Гостиничный комплекс "Гранд Отель" (название условное) имеет 100 номеров разной категории (Standard, Lux, Suite). В отеле работают: служба приема и размещения (Reception), служба горничных (Housekeeping), отдел бронирования и бухгалтерия. Система должна работать в локальной сети отеля и иметь веб-интерфейс для администраторов.

**3. Акторы и их цели:**
* **Администратор стойки регистрации (Receptionist):** быстро оформлять заселение/выезд, бронирования и оплату, чтобы минимизировать время ожидания гостя.
* **Горничная (Housekeeper):** получать список задач на уборку и отмечать статус номера, чтобы номера своевременно становились доступными для заселения.
* **Менеджер (Manager):** просматривать отчеты о загрузке и управлять тарифами, чтобы принимать решения по загрузке и ценообразованию.
* **Система онлайн-бронирования (внешняя):** передавать данные о брони в систему отеля через API.

**4. Границы системы (Scope):**
* Входит в систему (In Scope):  
  * Учет номерного фонда (статусы: свободен, занят, убран, ремонт).  
  * Оформление бронирований (текущих и будущих).  
  * Регистрация заезда (Check-in) и выезда (Check-out).  
  * Ведение картотеки гостей.  
  * Формирование счетов и учет оплат.    
  * Формирование отчетности для руководства.  
* Не входит в систему (Out of Scope):  
  * Бухгалтерский учет (1С) — только выгрузка данных.  
  * Управление рестораном и кухней (отдельная система).  
  * Сайт бронирования для физических лиц (система работает только для персонала, хотя может принимать данные с сайта через API).  
  * Управление кадровым учетом персонала.
 
**5. Допущения и ограничения:**
* Система работает только в локальной сети отеля; доступ извне — только через API для внешней системы бронирования.
* Предполагается, что физическое состояние номера соответствует его статусу в системе.
* Интеграция с 1С ограничена выгрузкой данных (без двустороннего обмена).

**6. Цель шага: Сформулировать единое понимание продукта для заказчика и команды разработки.**
