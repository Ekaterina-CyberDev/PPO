# **Activity Diagram (Диаграмма деятельности)**

**Выбранный процесс: "Заселение гостя (Check-in)".**  
Это самый критичный бизнес-процесс, затрагивающий интересы клиента и администратора.

**Описание процесса:**
1. Гость подходит к стойке.  
2. Администратор запрашивает документ (паспорт).  
3. Ветвление: Есть ли бронь?  
   * Да: Найти бронь в системе.  
   * Нет: Проверить наличие свободных номеров на текущую дату.  
4. Ветвление (Наличие номеров):  
   * Если нет — предложить альтернативу или отказ.  
   * Если есть — выбрать номер.  
5. Проверка статуса номера (должен быть "Чистый/Свободен").  
6. Ввод данных гостя в систему.  
7. Принятие оплаты (наличные/карта).  
8. Выдача ключа.  
9. Изменение статуса номера в системе на "Занят".  
10. Конец процесса.  


# Процесс заселения гостя  
```mermaid
flowchart TD
    Start((Начало)) --> Step1["Подход гостя к стойке"]
    Step1 --> Step2["Запрос документа"]
    Step2 --> Decision1{"Есть бронь?"}

    Decision1 -- Да --> Step3["Поиск брони в системе"]
    Decision1 -- Нет --> Step4["Поиск свободных номеров"]
    
    Step4 --> Decision2{"Номера есть?"}
    Decision2 -- Нет --> Step5["Отказ в заселении"]
    Step5 --> End((Конец))
    
    Decision2 -- Да --> Step6["Выбор номера"]
    
    Step3 --> Decision3{"Номер готов?"}
    Step6 --> Decision3
    
    Decision3 -- Нет (Грязный/Ремонт) --> Step7["Предложить другой номер"]
    Step7 --> End
    
    Decision3 -- Да --> Step8["Ввод паспортных данных"]
    Step8 --> Step9["Оформление договора"]
    Step9 --> Step10["Прием оплаты"]
    Step10 --> Step11["Выдача ключа"]
    Step11 --> Step12["Смена статуса номера на 'Занят'"]
    Step12 --> End
